# PRレビュー対応

PRのレビューコメントを取得し、対応を支援します。

## 使用方法

```
/pr-feedback <pr-number>
```

引数: $ARGUMENTS（PR番号）

## 実行手順

### 1. コメント取得

```bash
# レビューコメント（コード行へのコメント）
gh api repos/{owner}/{repo}/pulls/{pr}/comments

# 一般コメント
gh pr view {pr} --json comments,reviews
```

### 2. コメント一覧表示

以下の形式で表示:

```
## PRレビューコメント一覧

| # | 種別 | 投稿者 | ファイル/行 | 内容（要約） |
|---|------|--------|-------------|--------------|
| 1 | 修正要求 | @reviewer | services.py:45 | 定数化してください |
| 2 | 質問 | @reviewer | - | なぜこの実装方式？ |
| 3 | 提案 | @reviewer | tests/test_*.py | テスト追加推奨 |
```

### 3. 各コメントへの対応選択

```
コメント#1: 定数化してください
投稿者: @reviewer
ファイル: services.py:45

【対応案】
- 対応種別: F（修正）
- 根拠: CLAUDE.md §7 マジックナンバー禁止
- 返信案: "修正しました。MAX_RADIUS_KM として定数化しました。"

[Y] 承認  [M] 修正  [N] 却下  [S] スキップ:
```

### 4. 対応実施

| 選択 | 対応内容 |
|------|----------|
| E（説明） | 返信コメント生成 → 投稿 |
| F（修正） | コード修正 → コミット → プッシュ → 返信投稿 |
| D（保留） | TASKS.mdにTECH-XXX追加 → 返信投稿 |
| S（スキップ） | 対応不要として記録のみ |

### 5. コメント返信投稿

```bash
# レビューコメントへの返信
gh api repos/{owner}/{repo}/pulls/{pr}/comments/{comment_id}/replies \
  -f body="返信内容"

# 一般コメント
gh pr comment {pr} --body "返信内容"
```

### 6. LOG.md更新

`tasks/<id>/LOG.md` の「PRレビュー対応」セクションを更新

### 7. PR本文更新（修正があった場合）

```bash
gh pr edit {pr} --body "$(cat <<'EOF'
（既存の本文）

## 追加修正（YYYY-MM-DD）
- 指摘対応: {内容}
- コミット: {hash}
EOF
)"
```

## コメント返信フォーマット

### 説明返信（E）

```markdown
> {元のコメント内容}

**判断:** {判断者}
**根拠:** {根拠}

{説明内容}
```

### 修正対応（F）

```markdown
> {元のコメント内容}

**判断:** {判断者}
**根拠:** {根拠}
**原因:** {なぜこの指摘が発生したか}
**対応:** {何をどう修正したか}

- コミット: {commit_hash}
```

### 保留（D）

```markdown
> {元のコメント内容}

**判断:** {判断者}
**根拠:** {根拠}
**理由:** {なぜ保留とするか}

次回タスク（#TECH-XXX）として対応予定です。
```

## 判断者の表記

| 判断者 | 表記 | 条件 |
|--------|------|------|
| ユーザー手動 | `@{username}（手動判断）` | ユーザーが明示的に指示 |
| エージェント承認済み | `Claude Code（@{username} 承認）` | エージェント提案をユーザーが承認 |
| エージェント自動 | `Claude Code（自動判断: {根拠}）` | SPEC/CLAUDE準拠の明確なケース |

---

## 自動判断の条件

以下の場合のみエージェントが自動判断可能（ユーザー承認不要）:

| 条件 | 例 |
|------|-----|
| SPEC.md/CLAUDE.mdに明確な規定 | マジックナンバー禁止、Docstring必須 |
| 既存パターンとの整合性 | 他ファイルと同様の実装 |
| 軽微な修正 | typo、フォーマット |

**それ以外はユーザー承認必須**

## LOG.md記録形式

```markdown
## PRレビュー対応（YYYY-MM-DD）

### 対応サマリー
| # | コメント | 判断者 | 対応 | 根拠 |
|---|----------|--------|------|------|
| 1 | 定数化してください | Claude Code（@y-ssk 承認） | 修正 | CLAUDE.md §7 |
| 2 | テスト追加推奨 | @y-ssk（手動判断） | 保留 | 優先度低 |

### 詳細

#### コメント#1: 定数化してください
- **投稿者:** @reviewer
- **判断者:** Claude Code（@y-ssk 承認）
- **根拠:** CLAUDE.md §7「マジックナンバー禁止」
- **原因:** 初期実装時に定数化を見落とし
- **対応:** `MAX_RADIUS_KM = 100` として定数ファイルに移動
- **コミット:** abc1234
```

---

## 注意

- 返信投稿前に必ず内容を確認
- 修正コミット後はCI通過を確認
- 複数コメントがある場合は順番に対応
- 責務不明瞭な判断は必ずユーザー承認を得る
