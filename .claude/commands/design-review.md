# 設計レビュー詳細解説

設計レビュー結果を詳細解説付きでドキュメント化します。

## 使用方法

```
/design-review <task_id>
```

**引数:**
- `task_id`: タスクID（例: `008`, `D007`）

## 出力先

```
docs/local/<task_id>_design_review.md
```

> ※ `docs/local/` は `.gitignore` に追加済み（ローカル専用）

## 実行手順

1. タスク情報取得
   - `tasks/<id>/TASK.md` を読み込み
   - SPEC.mdの該当セクションを特定

2. senior-architect-reviewerエージェントで設計レビュー実施
   - SPEC整合性
   - アーキテクチャ準拠
   - 責務分離
   - 影響範囲
   - テスト可能性
   - 未定義事項

3. 各指摘事項を詳細解説形式でドキュメント化
   ```markdown
   ## N. 指摘タイトル【重要度】

   ### 何が問題か
   <問題の説明>

   ### なぜ問題か
   <背景・理由の説明>

   ### どうするか
   <具体的な対応方法とコード例>
   ```

4. まとめテーブルを追加
   ```markdown
   | # | 要約 |
   |---|------|
   | 1 | ... |
   ```

5. 対応選択肢を追加
   ```markdown
   - **Y**: すべて盛り込んで実装
   - **P 番号**: 一部のみ（例: `P 1,3,5`）
   - **S**: スキップ
   - **A**: 中止
   ```

## 出力フォーマット

```markdown
# タスク #<id> 設計レビュー詳細解説

> このファイルはローカル専用です（.gitignoreに追加済み）

---

## 1. 指摘タイトル【高/中/低】

### 何が問題か
...

### なぜ問題か
...

### どうするか
...（コード例含む）

---

## まとめ

| # | 要約 |
|---|------|
| 1 | ... |

---

## 対応選択肢

- **Y**: すべて盛り込んで実装
- **P 番号**: 一部のみ
- **S**: スキップ
- **A**: 中止
```

## 注意

- このスキルはワークフロー必須ではない（任意使用）
- 指摘事項の背景理解が必要なときに使用
- docs/local/ 配下は共有されないため、チーム開発時は別途共有手段を検討
